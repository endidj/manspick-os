# 출처·열람 범위·정합성 기준

현재 개발·검수 범위의 근거는 「맨즈픽 OS 개발 계약서」 2~3쪽이고, 고객 흐름의 근거는 4쪽이다. 기능 번호와 검수 기준은 [제품 요구사항](../01-product-requirements.md)에 정리했다.

아래는 2026-11-06 조사 기록이다. 당시에는 2026-10-03 업무 결정과 2026-10-04 데이터 모델을 검토했다. 가격·프로모션·잔여석은 당시 자료의 표기다.

## 1. 접근 복구 결과와 한계

Figma 연결 계정 확인은 성공했으나 파일용 네이티브 도구는 읽기 요청에도 편집 권한 오류를 반환했다. Notion 연결 도구는 Unknown tool 오류를 반환했다. 이를 사용자 계정의 파일 접근 불가로 단정한 이전 판단을 수정한다. **일반 브라우저에서는 두 원문의 본문과 내부 페이지가 열렸고, 이 경로로 조사했다.** 커넥터 자체가 정상 복구됐다고 주장하지 않는다.

Figma는 캔버스의 레이어 텍스트·프레임·노드·공통 요소를 읽었다. 원본 변수 컬렉션, 모든 속성/override, 댓글·프로토타입 연결·파일 바이너리를 완전 추출하지 않았다. Notion은 아래 본문과 DB의 표시 행을 검토했다. 모든 DB 행의 개별 페이지 본문·첨부 PDF·전체 HOME의 모든 운영 데이터까지 읽었다고 주장하지 않는다.

운영실 직접 링크 24개와 HOME 관련 회의 12개를 검토했다. 조사 중 연결 설정, 인증 정보, 공유 권한은 변경하지 않았다.

## 2. 초기 조사 당시의 충돌 판단 원칙

1. 사용자 고정 조건이 우선한다: Next.js/TypeScript/Yarn workspaces, admin/user/landing, design-system, CSS 최적화, 공개 index.ts, ESLint/Prettier. 최초 문서 단계의 코드 금지 후 로컬 1차 구현이 승인되었고 현재는 디자인 시스템 보완을 진행했다. Cloudflare 배포는 수행하지 않는다.
2. Figma를 화면·UX·컴포넌트·시각 기준으로 우선한다. 최신 Customer 화면·주석, D3 v0.2, D4 v0.4를 기준으로 삼는다.
3. 같은 파일 안의 오래된 D2/랜딩/운영 복사 문구가 최신 화면·날짜가 명시된 결정과 충돌하면 변경 이력과 함께 판정한다. 단지 Figma 안에 있다는 이유로 폐기된 규칙을 되살리지 않는다.
4. Notion Canonical v1.11과 10/3 의사결정 로그로 사업 규칙을 교차 검토한다. 화면에 아직 반영되지 않은 정책은 수정 대상으로 표시한다.
5. 최신 자료끼리도 충돌하는 경우 사실을 숨기지 않고 미결로 둔다. 설계 권고는 원문 확정과 구분한다.

과거 문서는 맨즈픽의 문제와 변화의 이유를 파악하는 근거다. 문서 안의 개발 에이전트 조직·회의 참석자를 앱 권한으로 변환하지 않는다.
