# 맨즈픽 1차 검수 미팅

2026-11-10 · 미팅용 제안. 300만원의 계약 범위는 아래 검수 기준을 바탕으로 합의한다.

> 예약이 들어오면 고객과 직원이 같은 촬영 건을 각자의 화면에서 봅니다. 직원은 입금을 확인하고 담당자를 배정합니다. 고객은 개인 링크에서 준비와 사진 선택을 진행합니다. 다음 담당자는 업무에 필요한 정보만 받아 처리합니다.

[공개 GitHub 검수본](https://github.com/endidj/manspick-os) · [공개 DB 설명](https://github.com/endidj/manspick-os/blob/main/docs/REVIEW.md)

## 미팅 전 준비

1. **첫 15분.** 공개 GitHub의 README와 DB 설명을 연다. 로컬 랜딩·고객·직원 앱을 띄우고 상태 확인 API와 직원 로그인, 고객 샘플 링크를 미리 확인한다. 공개본은 가상 이미지와 데이터로 실행한다.
2. **다음 20분.** 아래 시연을 한 번 리허설한다. 새 예약에 쓸 가상 이름과 연락처를 준비한다. 사진은 가상 PNG를 사용한다. 고객 역할과 직원 역할은 별도 브라우저 프로필에서 연다.
3. **마지막 15분.** 예약 접수 화면, 직원 보드, 권한 거부 응답을 순서대로 열어 둔다. 화면 연결이 끊기면 예약과 슬롯을 함께 저장하는 테스트, DB 관계도, 권한 거부 결과를 보여준다. 시연을 시작하기 전 사용 가능한 연락처와 슬롯을 한 번 더 확인한다.

검수 환경의 직원 보드에 `시연 리허설` 예약이 `입금 대기` 상태로 있다. 새 예약 접수가 지연되면 이 건을 검색해 입금 확인부터 보여줄 수 있다. 남은 10분은 화면 공유와 연결 점검에 둔다.

## 20분 진행 순서

| 시간    | 화면과 행동                                                                                                       | 설명할 내용                                                                                                                                 |
| ------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 0~2분   | 랜딩에서 상품을 보고 고객 앱 예약으로 이동                                                                        | 서비스 안내와 직원 업무를 각각 화면으로 나누고 같은 상품 정보를 사용한다.                                                                   |
| 2~7분   | `/start`에서 새 예약을 접수하고 직원 앱 대표 역할에서 같은 고객을 찾는다. 입금 확인까지 진행한다.                 | 고객 정보를 다시 입력할 필요가 없다. 예약·시간·입금 기록이 한 건에 묶인다. 이 시연의 입금 확인은 직원이 직접 처리한다.                      |
| 7~11분  | 고객 앱의 준비 샘플을 열고 설문·준비 안내를 확인한다. 셀렉과 결과 샘플로 후속 화면을 보여준다.                    | 개인 링크 하나에서 다음 할 일을 확인한다. 샘플을 전환해 각 단계의 화면을 보여준다.                                                          |
| 11~14분 | 보정가 역할로 결과 샘플을 열고 대표 화면과 비교한다. 고객 로그인으로 다른 촬영 URL을 요청해 거부 응답을 확인한다. | 보정가에게는 배정된 컷과 수정 요청이 보인다. 고객 연락처와 내부 메모는 서버 응답에서 제외한다.                                              |
| 14~17분 | GitHub의 DB 관계도와 검증 기록을 연다.                                                                            | 예약 하나를 두 사람이 동시에 잡을 때 하나만 저장한다. 상품 가격을 바꿔도 이전 예약 가격은 유지한다. 사진은 허용된 촬영과 단계에서 전달한다. |
| 17~20분 | 아래 검수표와 2호 고객사 배포 그림을 함께 본다.                                                                   | 오늘 인수할 범위, 실고객 투입 전 검증, 두 번째 고객사에서 추가할 업무를 구분해 합의한다.                                                    |

로컬 준비 샘플은 [촬영 준비](http://localhost:3001/s/demo-preparation-access) `1002`, [사진 셀렉](http://localhost:3001/s/demo-selection-access) `1003`, [보정 결과](http://localhost:3001/s/demo-result-access) `1004`다. 직원 앱은 [운영 보드](http://localhost:3002)에서 데모 역할을 선택한다. 운영 테스트 주소는 시연 링크로 공유하지 않는다.

## 300만원으로 받을 결과와 검수 방법

| 받는 결과                               | 현장에서 합격 여부를 확인하는 방법                                                                                             | 기대 효과                                                      |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 예약 접수·운영 보드·입금 확인의 한 흐름 | 고객이 접수한 이름·상품·일정이 직원 화면에 나오고, 입금 확인 후 진행 상태가 바뀐다.                                            | 예약을 채팅에서 스프레드시트로 옮기는 작업을 줄인다.           |
| 고객 개인 페이지와 직원 업무 인계       | 설문·준비·셀렉·결과 샘플을 열고 직원별로 다음 조치와 볼 수 있는 정보를 확인한다.                                               | 고객의 진행 확인 문의와 담당자 간 상태 확인을 줄일 수 있다.    |
| 핵심 DB 보호 장치와 자동 검사           | 같은 시간의 경합에서 예약 하나만 남고, 다른 고객의 사진 요청이 거부되며, 변경한 상품가가 과거 예약에 소급되지 않는지 확인한다. | 이중 예약, 결제 확인 누락, 사진 오발송을 줄이는 기반을 갖는다. |
| 소스·마이그레이션·실행과 인수인계 문서  | 새 작업 폴더에서 가상 데이터로 실행한다. 후임이 DB 변경 순서, 환경 설정, 테스트를 문서에서 찾을 수 있다.                       | 새 개발자가 수정할 위치와 검수 절차를 찾기 쉽다.               |

시간 절감 예시는 월 60건에서 예약당 10분을 줄이는 경우다. 월 10시간에 내부 운영 시간가치 2만 5천원을 적용하면 월 25만원이고, 개발비 300만원을 이 항목만으로 회수하는 단순 계산은 12개월이다. **60건·10분·2만 5천원은 가정**이다. 시범 운영 전후의 예약당 직원 처리 시간, 일정 정정 건수, 진행 확인 문의 수를 같은 기준으로 측정한다. 인프라와 유지보수 비용은 이 산식과 개발비 범위에서 따로 합의한다.

## 실고객을 받기 전에 합의할 것

- **1차 검수 범위.** 로컬에서 재현한 흐름과 테스트 결과로 인수한다. 결제 공급자 연동, 자동 알림톡, 운영 발송·도메인·배포, 기존 고객 이관, 타사 배포는 별도 범위와 인수 기준을 정한다.
- **데이터 운영.** 직원 등록·회수 책임자, D1 복구와 R2 복구 담당자, 고객 정보·사진 보존과 삭제 기준, 장애 시 대응 시간을 정한다. 스테이징에서 실제 메일 수신, 권한 거부, 복원한 기록과 객체의 연결을 확인한다.
- **소유권과 인수.** 저장소, 도메인, Cloudflare 계정 접근권한과 운영비 부담 주체를 정한다. 납품 코드의 사용 범위, 제3자 자산 권리, 공통 코드의 다른 회사 재사용 범위를 계약서에 명시한다.
- **2호 고객사.** 브랜드·도메인·설치 설정을 바꾸고 직원 로그인과 권한이 있는 업무 한 건을 연결한다. A의 계정·세션·파일로 B에 접근할 수 없어야 두 번째 납품을 검수한다.
