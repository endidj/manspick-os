# 맨즈픽 OS 제품 요구사항

개발 범위는 「맨즈픽 OS 개발 계약서」 2쪽 기능표와 3쪽 지표 명세, 이용 순서는 4쪽 전체 서비스 유저플로우를 따른다. 계약대금 300만원은 2~3쪽의 모든 기능에 적용된다. 아래 번호는 계약서의 기능 번호와 같다.

## 고객 이용 흐름

**주문 페이지(예약 신청 포함) → 카카오 또는 구글로 가입·로그인 → 설문 페이지 → 일정 확정·촬영 안내 → 오프라인 촬영** 순서다. 예약 신청은 고객이 희망 일정을 제출하는 시점이고, 일정 확정은 담당 디렉터가 그중 하나를 고르는 시점이다.

| 단계                  | 고객과 시스템의 동작                                                                                                                                                                                                         |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 주문·예약 신청        | 직접결제 고객은 연동 결제창에서 결제가 승인되면 예약이 완료된다. 크몽·숨고 등에서 이미 결제한 고객은 맨즈픽 결제 단계를 건너뛰고 플랫폼 닉네임을 입력해 예약을 마친다. 두 경로 모두 희망 촬영 일시를 여러 개 제출할 수 있다. |
| 담당 디렉터 자동 배정 | 신청 옵션을 수행할 수 있는 디렉터 중 고객이 제출한 희망 일정에 가능한 사람을 찾는다. 후보가 여러 명이면 입사일이 가장 빠른 디렉터를 배정한다.                                                                                |
| 가입·로그인           | 주문 페이지를 마치면 신규 고객은 카카오 또는 구글 계정으로 가입하고 기존 회원은 로그인한다. 최근 사용한 로그인 수단을 표시하고, 인증이 끝나면 설문 페이지를 연다.                                                            |
| 설문·고객 프로필      | 설문 응답을 회원 정보와 함께 저장한다. 고객은 전용 페이지에서 본인 정보와 설문 상태를 확인한다. 전용 URL, 저장 방법과 분실 시 문의 방법을 안내한다.                                                                          |
| 일정 확정·촬영        | 배정된 디렉터가 고객의 후보 일정 중 하나를 확정하고 장소와 시간을 안내한다. 고객은 본인 예약에서 확인하고, 디렉터는 촬영 전·중·후의 할 일과 진행 상태를 관리한다.                                                            |

## 기능과 검수 범위

| 번호 | 기능                       | 확인할 동작                                                                                                                                                                                     |
| ---- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 풀스택 아키텍처 및 DB 설계 | 화면·서버·DB를 연결하고 회원·설문·주문·예약·디렉터·작업의 관계, 이용 기록과 입금 확정 내역을 저장한다.                                                                                          |
| 2    | 배포와 접근권한            | 의뢰인 관리 저장소·운영 환경에 배포한다. 고객은 본인 정보에, C레벨(2명)·CS·디렉터·보정가 등 직원은 각 역할에 허용된 정보에 접근한다.                                                            |
| 3    | 대표 화면                  | 직원 계정과 역할을 관리한다. 직원 추가·삭제 권한은 현욱에게만 부여하고, 삭제 시 계정을 비활성화해 기존 기록을 보존한다. 회원 정보, 주문·설문 상태, 예약 내용, 직원별 현재 담당 업무를 조회한다. |
| 4    | 운영직원 화면              | 고객 프로필·예약 내역·담당 디렉터·확정 일정·촬영 장소를 확인해 고객 문의에 응대한다.                                                                                                            |
| 5    | 디렉터 화면                | 본인에게 배정된 고객과 예약을 조회하고 일정을 확정하며 촬영 진행 상태를 관리한다.                                                                                                               |
| 6    | 랜딩·추천 페이지 이관      | 기존 랜딩과 추천 페이지의 콘텐츠·주요 동선을 이관하고 모바일 표시와 공유용 OG 이미지를 확인한다.                                                                                                |
| 7    | SEO 및 GEO 최적화          | 공개 페이지의 대표 주소·사이트맵·이미지 대체 텍스트를 정비하고, 상품 가격과 포함 내역을 본문과 구조화 데이터에 반영한다.                                                                        |
| 8    | 웹 성능 최적화             | 이미지 용량과 스크립트 로딩 방식을 조정하고 모바일·데스크톱에서 주요 페이지의 로딩 속도와 반응을 점검한다.                                                                                      |
| 9    | 주문 페이지·결제           | 고객용 주문 페이지에 결제 솔루션을 연동한다. 외부 결제 고객은 닉네임 입력 경로를 이용한다.                                                                                                      |
| 10   | 카카오·구글 가입 및 로그인 | 주문 이후 두 로그인 수단과 최근 로그인 방법을 표시하고 인증 후 설문으로 연결한다.                                                                                                               |
| 11   | 설문 페이지·고객 프로필    | 가입·설문의 누락과 중복을 처리하고 고객별 설문 응답·제출 상태·전용 URL을 확인한다.                                                                                                              |
| 12   | 디렉터 정보 관리           | 기본정보, 수행 가능한 상품 옵션, 가능한 날짜·시간, 입사일을 등록·조회하고 배정에 활용한다.                                                                                                      |
| 13   | 예약·디렉터 자동 배정      | 주문 페이지에서 제출한 복수의 희망 일정을 기준으로 옵션 수행 가능 여부, 일정 가능 여부, 빠른 입사일 순으로 담당자를 정한다.                                                                     |
| 14   | 일정 확정·촬영 안내        | 담당 디렉터가 후보 일정 하나를 확정하면 고객이 본인 예약에서 촬영 일시와 장소를 확인한다.                                                                                                       |
| 15   | 담당자 카카오톡 알림       | 새 예약의 담당 배정과 일정 확정 내역을 해당 고객 담당 직원의 **개인 카카오톡**으로 보낸다. 디렉터·CS·보정가 등 각 직원은 본인 담당 건의 알림만 받는다.                                          |
| 16   | 행동 로그 수집             | 랜딩 방문·섹션 이용, 주문 페이지 진입, 가입·로그인, 설문 시작·제출을 기록한다. 랜딩에서는 모바일과 데스크톱을 구분한다.                                                                         |
| 17   | 지표 확인 페이지           | 어드민과 별도의 페이지에서 아래 세 범주의 지표를 조회한다.                                                                                                                                      |
| 18   | 통합 검수·인계             | 실제 고객 흐름과 지표 반영을 함께 시연한다. 서비스와 지표 확인 페이지의 전체 소스·DB 구조·운영 권한·배포 및 운영 안내를 의뢰인에게 인계하고, 실제 흐름에 맞게 도표를 갱신한다.                  |

## 지표 확인 페이지

| 구분           | 지표와 집계 기준                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 랜딩페이지     | 모바일·데스크톱별 방문과 섹션별 이탈, 체류 시간, 클릭을 확인한다.                                                                                           |
| 주문 페이지    | 자사 주문 단계별 이탈 인원·이탈률을 확인하고, 입금 확정 건수는 결제 기록에서 집계한다. 외부 플랫폼에서 이미 결제한 고객은 자사 주문 이탈 집계에서 제외한다. |
| 주문 이후 전환 | 주문을 마친 고객 중 가입·로그인, 설문 시작·제출에 도달한 인원과 단계별 전환·이탈을 확인한다. 신규 가입과 기존 회원 로그인은 구분한다.                       |

검수 시 모바일과 데스크톱에서 랜딩 섹션을 방문·클릭한다. 주문 중 이탈한 사례와 결제 후 인증·설문 제출까지 마친 사례를 각각 시연해 단계별 인원과 입금 확정 건수를 대조한다. 추가·옵션 구매율, 예약당 평균 결제액, 예약 종류·취소율, 예약 후 지연, 디렉터별 처리량·소요시간 통계는 계약 지표에서 제외한다.

의뢰인은 결과물 수령 후 5영업일 안에 검수 완료 여부 또는 보완사항을 회신한다. 중대한 오류는 보완 후 다시 확인하고 경미한 오류는 수정기한을 정한다. 계약 범위 전체의 검수와 인계가 끝나면 3영업일 안에 잔금을 지급한다.

## 구현 확인 경로

- 고객이 주문에서 여러 희망 일시를 제출하면 서버가 아이템 자격과 가능한 시간을 대조해 입사일 순으로 디렉터를 배정한다. 설문 제출 후 디렉터가 시간과 장소를 확정한다. [접수](../apps/server/src/booking/start.ts) · [일정 확정](../apps/server/src/shoots/commands/schedule-confirmation.ts)
- 실제 패키지와 아이템은 어드민에서 편집한다. 내부 사진은 권한 있는 직원에게 제공한다. 촬영 결과 전달은 네이버 클라우드, 보정 의견 교환은 카카오톡에서 운영한다. [DB 구조와 관계도](database.md)
- 계약은 직원 추가·삭제 권한을 현욱에게만 부여한다. 현재 API는 `admin` 역할로 이 권한을 검사하므로 관리자 계정이 여럿이면 모두 직원을 추가하거나 비활성화할 수 있다. [직원 계정 권한 검사](../apps/server/src/security/staff-accounts.ts)
- 테스트 환경에서는 직접결제 고객이 표시 금액을 확인하고 가상 결제를 승인하면 예약이 완료된다. 실결제는 PG 선정 및 연동 후 제공한다. 외부 플랫폼 선결제 고객은 예약 신청을 마치면 설문 단계로 진행한다. 기존 계좌이체 건은 직원이 수납을 확인한다.
- 직원 카카오 알림은 수신자별 발송 대기 상태로 저장한다. 메시지 발송사는 미선정이다. 카카오·Google 로그인은 각 앱의 클라이언트 ID·시크릿 및 등록된 콜백 주소가 있어야 활성화된다. 테스트 환경은 기존 개인 예약 링크 인증도 지원한다.
- 관리자 권한으로 지표 페이지 `/metrics`에서 랜딩, 주문, 인증·설문 퍼널을 확인한다. [지표 페이지](../apps/frontend-admin-page/src/app/metrics/page.tsx)
