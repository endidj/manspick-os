# 맨즈픽 프로젝트 작업 규칙

## 구현 전에 packages를 먼저 확인

이 규칙은 이 저장소에서 작업하는 모든 AI 에이전트와 하위 에이전트에 적용한다. 새 화면·컴포넌트·유틸을 만들기 전에 아래 순서로 기존 구현을 확인하고 재사용한다.

1. 관련 패키지의 `README.md`와 공개 `index.ts`/package exports를 읽는다. 사용할 수 있는 기존 컴포넌트·패턴·토큰·아이콘·자산·업무 함수를 먼저 찾는다.
2. 화면은 `@manspick/design-system/components`, `/patterns`, `/icons`, `/tokens`, `/assets`, `/styles`를 먼저 사용한다. 기존 props·variant·slot·조합으로 표현할 수 있으면 새 컴포넌트나 동일한 원시 마크업을 만들지 않는다.
3. 업무 규칙은 `@manspick/domain`, HTTP 클라이언트·Next 프록시·표시는 `@manspick/web`의 해당 공개 경로를 사용한다. 이미 존재하는 기능을 앱에 복사하지 않는다.
4. 기존 공통 UI가 필요한 표현을 지원하지 않으면 해당 컴포넌트의 역할과 호환성을 확인한 뒤 최소한으로 확장한다. 실제로 여러 화면에서 반복되는 표현은 디자인 시스템에 두고, 특정 업무의 데이터·권한·저장 로직은 앱/서버에 둔다.
5. 적절한 기존 구현이 없을 때만 새 구현을 추가한다. 작업 기록에는 재사용한 항목과 새 구현이 필요했던 이유를 간단히 남긴다. 새 의존성은 사용자가 요청한 경우에만 추가한다.

## 디자인과 패키지 경계

- Figma를 시각·배치·화면 흐름의 기준으로 삼고 기존 디자인 시스템 토큰과 대조한다. 확인하지 못한 화면·자산을 원본과 일치한다고 표현하지 않는다.
- 색상·폰트·간격·radius·상태 표현은 기존 토큰을 우선한다. 이미 있는 아이콘·폰트를 다시 그리거나 외부 라이브러리로 대체하지 않는다. 폰트·SVG 원본과 라이선스를 보존한다.
- 앱과 공통 컴포넌트의 색상·타이포그래피는 design-system의 semantic/type 토큰을 사용한다. 반복되는 HEX/RGB·글자 크기/굵기를 앱에 복사하지 않는다. 원본 화면에 필요한 값이 없으면 출처와 용도를 명시해 design-system에 먼저 추가한다.
- 앱별 레이아웃은 CSS Modules로 범위를 제한한다. 공용 스타일을 특정 앱의 요구로 전역 덮어쓰기하지 않는다.
- `domain`은 순수 업무 규칙, `apps/server`는 인증·인가·D1/R2·업무 처리, `contracts`는 요청·응답 타입, `web`은 앱과 API 연결, `design-system`은 표현을 소유한다. 디자인 시스템은 다른 업무 패키지에 의존하지 않는다.
- 화면 앱과 공통 패키지는 다른 앱의 실행부를 가져오지 않는다. API 계약은 `@manspick/contracts`에서 `import type`으로 가져오고 기존 프록시·클라이언트를 통해 요청한다.
- 앱에서 패키지의 `src` 내부 경로를 직접 가져오지 않는다. 필요한 공개 경로를 패키지에서 명시한다. `index.ts`는 재수출만 한다.

## 문서 배치

작업 기준은 `docs/`, 필요할 때 보는 상세 자료는 `docs/reference/`, 초기 계획과 과거 검증 결과는 `docs/archive/`에 두고 [문서 목차](README.md)에 연결한다. 각 디렉터리의 `README.md`와 도구가 자동으로 읽는 `AGENTS.md`는 해당 위치에서 관리한다.

## 구현·검증

- Next.js·TypeScript·Yarn workspaces·ESLint·Prettier를 유지한다. 화면 앱을 수정하기 전에 해당 앱의 `AGENTS.md`와 설치된 Next.js 로컬 문서를 확인한다. [앱별 규칙 목록](README.md#작업-기준)
- 소스·설정 파일 맨 위에 파일 역할을 쉬운 주석으로 설명하고 함수 사이에는 빈 줄을 둔다. 원본 자산·라이선스·JSON은 예외다.
- 리팩토링은 변경 계획과 기존 동작의 회귀 검사를 먼저 마련한다. 인증·권한·촬영 소유권·파일 보호·저장 실패 처리를 화면 변경 과정에서 약화시키지 않는다.
- 변경에 맞는 검사부터 실행하고 typecheck·lint·format·관련 테스트와 빌드를 확인한다. 공통 UI 동작을 바꾸면 관련 Storybook interaction·접근성 검사도 실행한다. 화면은 Figma와 데스크톱·모바일 렌더를 비교한다.
- Cloudflare 원격 리소스 생성·변경·배포는 수행하지 않는다. 로컬 D1/R2 데이터는 사용자 승인 없이 초기화하거나 삭제하지 않는다.
- 병렬 작업은 독립적이고 한정된 범위에만 사용한다. 하위 에이전트는 최대 2개·깊이 1이며 소유 파일을 나누고 다른 작업자의 변경을 되돌리지 않는다. 명시적으로 요청하지 않은 OMX 자동 실행 모드를 시작하지 않는다.
- 완료 보고에는 변경 내용·재사용한 패키지·검증 결과·남은 한계를 간단히 기록한다.
