# 공개 랜딩 이미지·폰트 최적화 계획

2026-11-17. 원본 디자인·동작·비율을 유지하면서 공개 웹 사진의 용량과 로딩을 개선한다.

1. 기존 메인/추천 브라우저 회귀 검사와 원본 비교 기록을 기준으로 화면을 유지한다. 초기 390px 빈 캐시 점검은 사진 2,252,782B, 폰트 517,012B였다.
2. 원본72개는 보존한다. 독립 생성 명령에서 자동 회전·sRGB 변환 후 메타데이터 없는 WebP 파생본을 만든다. 파일/옵션/도구 버전 해시와 출력 해시로 변경분만 생성하며 일반 앱 빌드에는 인코더를 넣지 않는다.
3. 정적·동적 갤러리 사진에 실제 슬롯에 맞는 srcset/sizes와 고유 크기를 제공한다. 작은 아바타는 작은 파생본을 사용한다. 갤러리는 열 때 생성하며 다음 슬라이드는 화면에 가까워졌을 때 미리 준비한다.
4. 디자인 시스템의 기존 폰트·자산 공개 경로를 재사용한다. PhotoTile은 선택/상태용 셸이므로 원본 레이아웃에 억지로 넣지 않고 앱 전용 이미지 어댑터로 원래 img 구조를 유지한다. 폰트는 공식 서브셋과 글자 범위를 유지하고 실측상 도움이 되는 최소 로딩 힌트만 추가한다.
5. 출력 메타데이터 부재·방향·알파·치수·원본 무변경·캐시 재사용/복구를 검사한다. 모든 화면 이미지 디코딩, srcset 선택, 슬라이드 교체, 메뉴/모달/추천, 390/1440px 배치·색감·화질을 확인한다.
6. 타입·린트·포맷·관련 단위/브라우저 검사·빌드를 수행한다. 기존 공개 저장소 이력을 보존해 커밋·푸시하고 기존 테스트 랜딩에 배포한다. 검색 제외 정책은 유지한다. 고객 비공개 파일·API·DB는 이 변경에 포함하지 않는다.
