# 랜딩 정적 생성과 선택 기능 코드 분할 계획

## 범위와 기존 동작

- 사용자 요청: 가능한 랜딩 페이지를 SSG로 전환하고, 효과적인 코드 분할을 적용하며, 원본 SEO100/이식본69의 Lighthouse 차이를 실제 검사로 설명한다.
- 검색 제외는 앞선 사용자 요청을 유지한다. 점수를 올리기 위해 noindex를 해제하지 않는다.
- 기존 본문·사진·스타일·폰트·추천 쿼리 URL·모달 키보드/포커스·애니메이션을 유지한다. API/DB/고객 데이터와 관리자·고객 앱은 변경하지 않는다.
- 변경 전 배포에 기존 브라우저 회귀9개를 실행한다. 추가 검사는 사전 생성 산출물과 실제 응답, 선택 기능의 네트워크 로딩 및 닫기/언마운트 경합에 집중한다.

## 구현

1. 설치된 Vinext/Cloudflare 어댑터와 Next 문서에서 사전 생성 및 동적 경로 제외 동작을 확인한다.
2. 요청별 값이 필요 없는 메인·이용약관·개인정보 페이지를 사전 생성하고 기존 ASSETS 바인딩으로 제공한다. 정적 메타데이터도 빌드 산출물을 확인한다. 추천 페이지는 쿼리에 따른 최초 화면을 유지하도록 SSR에 남기며, API와 query 보존 리다이렉트도 서버에서 처리한다.
3. 기존 서버 본문을 유지하며 갤러리 등 선택 기능과 이미지 URL 정보를 별도 모듈로 옮겨 필요할 때 import한다. 이미 지연 로딩하는 Chart.js와 초기 필수 효과는 재사용한다. 공용 디자인 시스템의 자산/토큰 API를 유지하고 새 의존성을 추가하지 않는다.
4. 두 주소를 같은 Lighthouse 버전·설정으로 검사해 실패 audit와 가중치를 기록한다. 의도한 검색 제외 외의 결함이 있으면 수정한다.

## 확인과 배포

- 전체 타입·린트·단위 검사, 변경 파일 포맷, 배포용 빌드와 기존/추가 브라우저 회귀를 확인한다.
- HTML/RSC 사전 생성 파일, 처음부터 들어 있는 본문·메타데이터, SSR에 남은 추천 query와 API 경계, 내부 정적 캐시 파일의 직접 접근 차단을 확인한다.
- 분할 전후 실제 청크 크기와 첫 화면/클릭 후 요청을 확인한다. 큰 인물 사진과 이미지 메타데이터 제거 상태를 유지한다.
- 공개 저장소 이력에 이번 변경만 통합하고 커밋·푸시·기존 랜딩 Worker 배포 후 실제 주소를 다시 검사한다. 5개 앱의 검색 제외를 재확인한다.
