# 1인 AI 활용 개발의 범위·공수·예산 추정

작성일: 2026-11-06. 대상: 맨즈픽 OS의 19개 요구사항·86개 수용 기준, Next.js 3앱·단일 design-system, Cloudflare Workers/D1/R2 전환. **아래 시간과 일정은 이 프로젝트를 분해한 계획 추정이며 시장 단가·견적 보장·검증된 생산성 통계가 아니다.**

## 1. 판단

**1인+AI·4주·300만원으로는 범위를 정한 로컬 MVP를 목표로 삼는 것이 타당하다. 86개 수용 기준과 운영 출시 검증을 모두 포함하는 확정가·확정 납기로 받아들이기에는 위험이 크다.** 전체 범위는 집중 작업 8~12주를 우선 추정하고, 정책 결정·메일/알림톡 승인·피드백 대기는 별도로 고려한다.

월60명이라는 이용량보다 예약 경합, 역할별 개인정보 차단, 사진 처리, 7단계 상태, 수정3회, 후기와 원본의 원자적 연계가 작업량을 만든다. Supabase에서 Cloudflare로 변경하면서 직원 인증·RLS 대체·D1 원자성·private 파일 전달을 직접 설계·검증해야 하는 점도 포함한다. [PRD](../01-product-requirements.md), [Cloudflare 설계](../07-cloudflare-architecture.md)

AI는 반복 UI·타입·검증 코드의 초안을 줄일 수 있다. 그러나 충돌한 정책의 최종 결정, 실제 고객 문구, 공급자 승인, 데이터 유출·동시 예약·복구 검증을 대신 완료하지 않는다. AI가 작성하는 속도를 그대로 검수 완료 속도로 환산하지 않는다.

| 통합 품질·운영 준비                | 악용/동시성/E2E·시각·접근성·성능·복구·인수인계            |       40~56시간 |
| 정책·계약·수정 반영                | 취소·기한·보존·약관 충돌 정리와 API/데이터 계약           |       16~24시간 |
| 합계                               | 중복 계산을 피한 직접 작업 범위                           | **276~408시간** |

직접 작업에 15~20%의 불확실성 여유를 두면 약 **320~490시간**, 주40시간 기준 **8~12주 수준**이다. 12주를 반드시 넘지 않는다는 상한 보장은 아니다. Windows/OpenNext 문제, 운영 권한/도메인 준비, 파일 규모, 정책 변경이 커지면 다시 추정한다. 외부 템플릿 승인 대기는 해당 개발 공수에 같은 시간만큼 더하는 대신 실제 달력 지연으로 기록한다.

이 추정은 근거가 있는 계획 분해지만 기존 팀의 실측 속도는 없다. 첫 1주 후 실제 소요·남은 항목·실패 사례로 갱신한다. 화면 개수만으로 공수를 환산하거나 AI 사용을 이유로 일괄 절반 삭감하지 않는다.

## 4. 4주·160시간에서 선택할 로컬 MVP

최소 목표는 **신규 고객 1건이 접수→예약→수동 입금 확인→설문을 완료하고 직원이 같은 데이터를 처리하는 흐름**이다. 시간 여유가 확보되면 코디→후보→셀렉→보정→후기/원본 해제의 7단계 정상 경로까지 확장한다. 후반 화면이 존재한다는 이유로 모든 변형·권한·자동화가 완성됐다고 보고하지 않는다.

| 주차 |       예산 시간 | 우선 범위·종료 증거                                                                         |
| ---- | --------------: | ------------------------------------------------------------------------------------------- |
| 1    |       35~40시간 | 3앱·design-system·단일 API Worker·D1/R2 지속성, 고객/직원 인증 골격과 역할 거부 사례        |
| 2    |       35~40시간 | 패키지·기본정보·시간 선택·원자적 슬롯 확보·hold·직원 입금 확인, 중복/경합 테스트            |
| 3    |       30~40시간 | 설문 자동저장·제출·기한 표시·최소 파일 업로드, 직원 촬영 상세/코디 또는 후반 정상 경로 착수 |
| 4    |       30~40시간 | 확보된 범위의 후반 업무·7단계 정상 흐름 확장, 악용/재시도/E2E·3앱 검사·남은 범위 기록       |
| 합계 | **130~160시간** | 검증된 최소 흐름을 우선 인수. 전체 86AC 충족 선언은 별도 근거 필요                          |

4주 안에 문제가 발견되면 검증 시간을 삭제해서 화면을 채우지 않는다. 핵심 인가·예약 원자성·데이터 지속성을 유지하고 후반 변형·UI 세부·운영 연동을 다음 단계로 넘긴다. 어느 AC가 완료/부분/미착수/외부대기인지 목록에 남긴다.

### 4주에 자동 포함하지 않는 범위

- Figma 고객23화면·직원 모든 화면의 완전한 시각 재현과 모든 responsive variant.
- 모든 부가서비스 조합·올데이/쇼핑/휴무 변경·취소·재배정·오입금·추가 결제의 전체 예외.
- 실 메일·알림톡 계정/도메인/템플릿 승인과 운영 발송, Cloudflare 운영 배포.
- 대량 사진·원본 전량 업로드·Range/재개·보존/삭제·복구의 운영 수준 검증.
- 전체 관리자 설정·캠페인 편집·운영 모니터링·백업 복구와 법무 문구 확정.

이 항목은 전체 제품 요구에서 삭제하는 것이 아니라 4주 로컬 인수 범위와 구분하는 것이다. 원본 해제 API만 구현한 경우 실제 원본 업로드·다운로드가 남아 있다고 명시한다. 개발용 로그인 링크·발송 outbox는 운영 메일/알림톡의 대체 완료로 세지 않는다.

## 5. 300만원 예산의 해석

300만원을 160시간 전체에 배분하면 시간당 18,750원, 130시간이면 약 23,077원이다. 이는 **주어진 예산을 나눈 산술값**이며 개발자의 시장 단가나 적정 보수에 대한 주장이 아니다. 세금·사업비·AI 이용료·운영 인프라·알림/메일 이용료를 포함할지에 따라 실제 투입 가능 범위가 달라진다.

| 조건                  | 권고 계약·인수 방식                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------- |
| 예산300만원·4주 고정  | 완료할 핵심 로컬 흐름과 제외/후속 항목을 명시한 1차 MVP. 미완료 AC를 숨기지 않음          |
| 전체19REQ·86AC 고정   | 8~12주 계획을 기준으로 구현·검증 범위와 예산을 재산정                                     |
| 일정4주·전체범위 고정 | 1인+AI로 검증 가능한 확정 약속은 어려움. 품질·권한·동시성을 생략하는 방식으로 맞추지 않음 |

범위를 줄이더라도 토큰/역할 인가·슬롯 경합·민감 파일 비공개를 옵션 품질로 빼지 않는다. 시각 세부·고급 운영 자동화·관리 편의 기능부터 후속 단계로 분리한다.

## 6. 로컬 인수와 운영 출시의 구분

| 단계           | 인수 기준                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 현재 로컬 1차  | 명시한 사용자 흐름 실제 수행, D1/R2 지속성, 권한 거부·예약 경합, format/lint/typecheck/build, 실행한 테스트와 미실행 범위 기록 |
| 후속 로컬 완성 | 19REQ/86AC 추적, 모든 역할·상품 조합·파일·수정·후기·기한·재시도, OpenNext workerd preview까지 검증                             |
| 운영 출시      | 별도 배포 요청·환경 준비, 실제 도메인/메일/알림톡, 비밀·private 경로·백업/복구·모니터링·정책/약관 게이트 통과                  |

운영 판단에는 [기존 출시 게이트](06-decisions-and-delivery.md)를 Cloudflare 기술로 대체 적용한다. 가격·무제한수정/3회·재촬영·보존·취소·당일납기·원본전량즉시 등 공개 문구 충돌도 그대로 남는다. 이번 로컬 구현이 해당 사업 정책을 대신 확정하지 않는다.

## 7. 첫 주 후 재추정할 증거

1. 세 앱과 API Worker를 한 명령 체계로 시작·종료하고 재시작 후 상태가 유지되는가.
2. 고객 접수와 역할별 접근을 실제 API·화면에서 검증했는가.
3. 같은 슬롯의 동시 예약과 무변경 UPDATE 실패에서 부분 반영이 없는가.
4. 실제 작업 시간이 계획과 얼마나 차이나며 후반 사진·보정 업무에 얼마가 남는가.
5. 외부 연동과 정책의 책임자·대기 상태가 확인됐는가.

이를 근거로 다음 3주의 완료 범위를 갱신한다. 예상 공수·로컬 동작·운영 출시를 각각 따로 보고하며, 배포는 이번 요청 범위에 포함하지 않는다.
