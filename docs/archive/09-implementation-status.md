# 로컬 1차 구현 현황

> 1차 구현 당시의 범위와 검증 결과를 보존한 기록이다. 현재 작업에 사용할 문서는 [문서 목차](../README.md#작업-기준)에서 확인한다.

작성일: 2026-11-06. 기준: 현재 저장소의 Next.js 3앱, 단일 API Worker, D1/R2 로컬 실행과 통합 검증. 이 문서는 [PRD의 19개 요구사항·86개 수용 기준](01-product-requirements.md)을 모두 충족했다는 완료 선언이 아니다.

**최신 고객·관리자 정밀 재구현은 [13번 Figma 대응 기록](../reference/13-figma-parity.md)을 우선한다.** 아래 표와 검사 수는 앞선 1차 구현 당시의 기록이다. 이후 준비 확인·현장 체크·수동 재배정·추가 보정 입금·상품 노출/편집·안내 조건과 수동 완료·설정 변경 이력 등을 추가했으므로 아래의 당시 미구현 목록을 현재 상태로 해석하지 않는다.

이후 운영 보강에서 직원 이메일 로그인 경로, 고객 링크 수동 발급·폐기, 전체 보드 검색·페이지 나누기, 예약 충돌과 만료 후 재예약, 컷별 보정 완료 검사를 추가했다. 실제 발송 설정과 인수인계, 회사별 배포 권고는 [타사 납품과 운영](../reference/10-client-admin-architecture.md)에 있다. 아래 표는 변경 이력으로 보존한다.

2026-11-10에 랜딩·고객·관리자 앱의 Workers 빌드와 개발 실행을 Vinext 1.4.4로 전환했다. 세 앱은 `@manspick/web/proxy`와 `MANSPICK_API` 서비스 바인딩을 공유한다. 별도 Vinext Node 빌드에서 랜딩 렌더, 공개 API 전달·보호 API 차단, 고객 개인 링크의 보호 헤더를 확인했다. 당시 Windows Application Control이 `workerd.exe` 실행을 차단했다. 문서 정리 후 `node scripts/build.mjs`로 세 앱의 Workers 산출물과 API 번들 생성을 확인했다. 로컬 preview와 실제 서비스 바인딩 통합 실행은 남아 있다. [Cloudflare 아키텍처](../07-cloudflare-architecture.md)

## 1. 현재 인수할 수 있는 범위

**실제 로컬 데이터와 파일을 공유하는 첫 버전이다.** 랜딩에서 서비스를 살펴보고, 고객 앱에서 신규 접수와 개인 여정을 체험하며, 직원 앱에서 같은 촬영을 역할에 맞게 조회·처리할 수 있다. 세 앱의 화면 재구성과 공용 DS 적용, 대표 브라우저·반응형 확인을 마쳤고 마지막 고객 앱 CSS 수정 후 최종 빌드도 통과했다. 실제 예약·송금·외부 메시지 발송·Cloudflare 운영 배포는 수행하지 않는다.

## 2. 로컬 인증과 데이터의 의미

고객은 개인 링크에서 뒤4자리를 확인한다. 신규 접수의 체험용 링크·뒤4자리는 로컬 모드에서만 응답에 표시한다. 기존 번호에 진행 중 촬영이 있으면 중복 생성과 기존 링크 응답 노출을 막지만, 그 번호로 실제 알림톡을 보내는 기능은 아직 없다.

직원 앱의 역할 선택은 **운영용 로그인 기능의 대체 완료가 아니다.** `LOCAL_DEMO=true`와 로컬 호스트 조건에서 가상 활성 직원으로 세션을 만드는 체험 경로다. 실제 직원 이메일 인증·발송·퇴사 관리·복구를 검증해야 운영 인증이 완성된다. 고객·직원 세션은 별도 쿠키와 앱 표면 구분을 사용하며 최종 인가는 API Worker에서 다시 수행한다.

원장과 파일은 로컬 D1/R2에 저장한다. seed의 샘플 촬영 이미지는 `LOCAL DEMO` 표시가 있는 SVG로 제공되며 실제 고객 사진이나 촬영 성과가 아니다. 신규 파일 업로드는 실제 R2 로컬 바인딩을 사용한다. 고객 파일에는 public 버킷 URL을 제공하지 않으며 보호 API가 인가 후 응답한다.

업로드 검사는 장당10MB·MIME과 매직 바이트·PNG 해상도 확인 수준이다. JPEG/WebP 전체 디코딩, EXIF 제거, 자동 축소·재인코딩은 구현하지 않았다. 보정 완료는 현재 작업에 새 결과가 최소1장 있는지 확인하지만, 선택한 모든 컷에 결과가 1:1로 대응하는지 검사하지 않는다.

현재 결제 경로 선택에는 계좌와 크몽·프립·숨고·스마트스토어가 있지만 **모두 로컬 직원 확인 흐름**을 사용한다. 플랫폼에서 실제 결제 여부를 조회하지 않고, 선결제 자동 확정과 금액 불일치 처리의 원문 정책을 완전 구현했다고 주장하지 않는다.

## 3. 직접 체험할 정상 흐름

1. [고객 /start](http://localhost:3001/start)에서 테스트 이름·번호·패키지·일정을 선택한다. 완료 화면의 로컬 개인 링크로 들어가 뒤4자리를 확인한다.
2. [직원 앱](http://localhost:3002)에서 대표 또는 운영 직원 역할로 같은 예약을 열어 입금 확인을 처리한다. 실제 송금은 하지 않는다.
3. 고객이 설문을 저장·제출하고 테스트 얼굴/의상 이미지를 올린다. 직원 또는 배정 디렉터가 컨셉·의상 제안과 메모를 공유한다.
4. 담당자가 촬영 상태를 진행한 뒤 후보를 업로드하고 별도로 셀렉을 연다. 고객이 기본 장수를 선택하면 보정 작업이 생성된다.
5. 보정가가 배정 작업과 마스킹된 사진·보정 선호를 확인하고 결과를 업로드한다. 보정 완료 동작으로 고객에게 공개한다.
6. 고객이 필요하면 여러 사진의 의견을 한 요청으로 보낸다. 최대3회 제한과 현재 수정 작업의 새 결과 최소1장 확인을 적용한다.
7. 고객이 후기 캡처를 올리고 직원이 확인하면 claim과 원본 공개가 함께 반영된다. 원본 업로드·다운로드는 R2를 사용한다.

이는 구현된 대표 경로를 설명한다. 모든 브라우저에서 이 전체 순서를 자동 E2E로 반복 검증했다는 뜻은 아니다. 샘플은 [README의 4개 개인 링크와 번호](../../README.md#체험-데이터)로 각 구간을 바로 살펴볼 수 있다. 샘플을 조작하면 상태가 실제로 바뀌므로 처음 보이는 단계는 초기 seed와 다를 수 있다.

## 5. 운영 전 남은 주요 작업

- 직원 이메일 매직링크·직원 등록·역할 변경·비활성화·전체 세션 회수를 구현했다. 실제 발송과 운영 도메인, 운영 호스트의 데모 경로 차단을 스테이징에서 확인한다. [운영 설정](../../apps/server/README.md#환경과-검사)
- 알림톡 업체 선정·템플릿 승인·이메일 발송, outbox 소비·중복 방지·재시도·발송 이력. 현재 대기 기록은 발송 성공이 아니다.
- hold 만료 해제, 8주 앞 슬롯 생성, 마감/전날 리마인드, 당일 상태 변경을 위한 예약 작업과 시간대 검증. 계산 함수와 수동 API만으로 cron이 완성되지는 않는다.
- 추가 보정·설문 추가 옵션 결제, 플랫폼 선결제·오입금·환불, 재예약 전용 업무·휴무/재배정과 취소 시 담당자 기록의 최종 정책.
- Figma 변수/variant 연결, 세 앱 전체 상태·역할/브라우저와 픽셀 정밀 검토, 실제 콘텐츠·공식 카카오 링크·상품 안내 정합성. 브랜드 사진47개는 원본 PNG와 앱용 WebP로 가져왔으며, 검증되지 않은 후기·언론·성과 수치를 가상 데이터로 채우지 않는다.
- 무제한 수정 대 3회, 무료 재촬영, 당일 보정 대 평균1~3일, 원본 즉시 제공 대 후기 후 해제, 1년 보존 대 삭제 요청까지 보존 등 원문 충돌의 정책 확정·약관 개정. 현재 `/legal`은 정식 약관이 아니다.
- 개인정보 동의 문구·버전, 보존/삭제·포트폴리오 철회, 접근·변경 감사 기록의 운영 수준 완성, 비밀 관리·백업/복구·장애 관측·대량 파일 처리·EXIF 제거/자동 축소·셀렉 컷별 결과 대응 검사.
- Vinext Workers 로컬 preview와 `MANSPICK_API` 서비스 바인딩 통합 테스트, 운영 리소스·도메인·배포 확인.

## 6. 다음 범위와 공수

다음 단계는 AC별 완료·부분·미착수·외부 대기 상태를 매핑하고, 현재 정상 경로에서 벗어나는 예외와 운영 연동을 순서대로 구현하는 것이다. [기존 출시 게이트](06-decisions-and-delivery.md)에는 Cloudflare 전환을 적용하고 정책 충돌을 그대로 추적한다.

[공수 추정](08-scope-estimate.md)은 직접 작업 276~408시간에 불확실성 여유를 더해 **약 320~490시간·8~12주**를 전체 범위의 초기 계획으로 잡는다. 외부 승인 대기는 별도이며 고정 납기를 보장하지 않는다. **1인+AI·4주·300만원은 범위를 정한 로컬 MVP 조건**으로 다루며, 이번 첫 버전이 86AC 전체·실제 운영 출시까지 충족했다는 의미로 사용하지 않는다.
