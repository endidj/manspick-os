# 랜딩 추가 성능 최적화 계획

## 기준과 범위

사용자가 favicon을 포함한 상세 감사를 요청한 뒤 확인된 최적화 전체 적용을 요청했다. 원본 디자인·모션, React/SSG/SSR 경계, 검색 제외, 고객·관리자 업무 동작을 유지한다. 기존 배포 `0e930a3d-e303-48e4-9b85-84debcc25ecd`와 구현 `abbeb4e`가 비교 기준이다.

감사 결과는 `.local/performance-audit/`에 보존한다. 모바일 초기 폰트 517,012 B, HTML 원시 708,488 B/전송 약 60 KB, 공용 CSS의 미사용 규칙, 큰 ICO와 갤러리 sizes 불일치를 확인했다. Lighthouse 모바일 2회는 성능 40/62로 편차가 있어 점수를 고정 보장하지 않는다. 두 검사 모두 메인 스레드·레이아웃 작업이 병목이었다. 화면 아래 렌더를 지연하는 브라우저 내 실험에서 초기 LayoutDuration이 0.56–0.60초에서 0.21초로 줄었다. 이는 적용 완료 수치가 아니다.

## 변경 순서

1. 기존 브라우저 11개 검사와 모바일/데스크톱 화면 좌표·이미지 선택·폰트 전송량을 기준으로 삼는다. 모달 viewport 위치, 해시 이동, 페이지 재진입, 화면 밖 렌더 후 좌표를 추가 검사한다.
2. 원본 favicon을 보존하고 작은 PNG 프레임 ICO 및 별도 고해상도 아이콘을 명시적 생성한다. 일반 빌드에서 변환하지 않는다. 새 콘텐츠 해시 URL을 사용한다.
3. 갤러리의 실제 3열 크기에 sizes를 맞춘다. 기존 사진 포맷·메타데이터 제거와 품질을 유지하며, 근거 없이 모든 사진 품질을 낮추지 않는다.
4. 랜딩 고정 문자용 폰트를 생성하고 원본을 fallback으로 보존한다. 가변 굵기·라이선스를 유지하고 생성한 파생 폰트 이름을 구분한다. 새 앱 런타임 의존성 없이 명시적 생성 도구와 재현 정보를 둔다.
5. 랜딩에서 쓰지 않는 앱 전용 CSS를 제외하고 공용 필수 스타일은 한곳에서 재사용한다. 약관·개인정보는 랜딩 전체 utility/animation CSS 대신 실제 사용 규칙만 가진 CSS Module을 사용한다.
6. 공용 아이콘의 반복 inline 고정 스타일을 CSS로 옮겨 HTML/RSC를 줄인다. 색상·크기·마스크·사용자 style override·접근성 API는 그대로 유지하고 Storybook에서 검사한다.
7. 화면 밖 섹션의 렌더와 효과를 지연한다. fixed 모달이 containment 안에 갇히지 않도록 먼저 바깥으로 옮긴다. 화면에 들어오면 원본 효과를 재개하며 스크롤·앵커·축소 모션·인쇄를 검증한다.
8. 변경 해시가 붙은 이미지·폰트·CSS·JS의 장기 캐시와 SSG 빌드별 캐시 격리를 확인한다. 동적 추천/API에 공용 장기 캐시를 추가하지 않는다.

## 검증과 공개 배포

- 타입·린트·단위·변경 파일 포맷, 공용 아이콘 Storybook, 기존/추가 브라우저 회귀, 배포용 SSG 빌드를 확인한다.
- 원본과 새 빌드의 모바일/데스크톱 화면·주요 좌표·이미지 선명도·가변 폰트·콘텐츠를 비교한다.
- 공개 이력에는 이번 커밋만 반영하고 기존 랜딩 Worker만 배포한다. 배포 후 HTML/RSC 캐시·파일 해시 갱신·5개 앱 검색 제외를 확인한다.
- 최종 파일/전송량과 성능 재측정은 실제 결과만 보고한다. 브라우저에서 이미 열린 탭을 강제 갱신한다고 약속하지 않는다.
