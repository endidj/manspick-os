# 결정 기록·미결 사항·구현과 출시 계획

> 아래 패키지 경로는 원문 조사 당시의 설계다. 현재 실행부는 `apps/server`, 공유 타입은 `@manspick/contracts`다. [서버 README](../../apps/server/README.md)

작성일: 2026-11-06 · 현재 단계: 실제 원문을 반영한 설계 문서 정리. 애플리케이션 구현·DB 적용·배포는 시작하지 않았다.

## 1. 결정의 근거와 지위

최신 제품 기준은 [Canonical v1.11](https://app.notion.com/p/Canonical-Manspick-OS-398af8f3d6b0817d9a84da6b2e770aca), [의사결정 로그](https://app.notion.com/p/3628104e799d4f4db6ca20cc0e1e44fd), 실제 Figma 고객/직원 화면과 [D3 API·권한 v0.2](https://www.figma.com/design/cDXVLqZAaWwZeyIo5pqnNl/?node-id=172-2), D4 데이터 모델 v0.4다. 자료 버전·내부 링크·열람 범위는 [출처 대장](../reference/00-sources-and-traceability.md)을 따른다.

- **사용자 고정**: 이 채팅의 직접 조건. 설계의 필수 제약이다.
- **원문 정책**: 실제 읽은 서비스 문서의 현재 기준. 서로 충돌하면 미결로 기록한다.
- **설계 보완**: 요구를 실현하기 위한 채택 기본안. 원문에 있었다거나 운영 검증을 마쳤다고 표현하지 않는다.
- **미결**: 구현·출시 전 운영 결정을 기록해야 하는 부분. 질문 목록을 한꺼번에 사용자에게 넘기기보다 확인한 출처와 좁혀진 선택지를 근거로 정리한다.

화면 구성과 사용 흐름은 Figma를 우선한다. 오래된 내부 화면 문구·약관·추천 페이지까지 자동으로 최신 정책이 되는 것은 아니다. 실제 화면 버전·문서 날짜·명시된 폐기 결정을 비교하고, 날짜 하나만으로 충돌을 숨기지 않는다.

Figma Website Desktop 14개 섹션에서 확인한 공개 카피는 최신 OS의 가격·보정·원본 정책과 대조한다. Notion HOME 상위의 회의록 12개는 2025년~2026년 1월의 역사적 운영 맥락이며 최신 Canonical의 제품 정책을 대체하지 않는다.

## 8. 첫 통합 업무 흐름

기본 성공 경로는 **신규 고객·계좌 결제·추가 옵션 없는 패키지**를 대상으로 하되 7단계를 모두 지난다. 한 개 화면이나 예약까지만 완료하는 작업 묶음으로 제한하지 않는다.

1. 직원이 카카오로 `/start` 최초 링크 전달. 고객이 패키지·기본정보 입력.
2. 고객 일정 선택 → book_slot이 후보 디렉터·휴무·슬롯을 재검증하고 자동 배정·hold 생성.
3. 직원이 계좌 입금 확인 → confirm_payment가 예약 상태·기한·타임라인·알림을 반영.
4. 고객이 개인 링크·뒤 4자리로 접속 → 4페이지 설문 자동 저장·최종 제출.
5. 디렉터가 배정 촬영의 코디안 작성 → share_plan → 9개 준비 안내·고객 확인·의상 업로드.
6. 당일 상태·의상별 진행 기록 → 촬영 종료와 셀렉 주체 확정.
7. 디렉터가 후보 업로드 → 실패 항목만 재시도 → 별도 셀렉 열기로 shortlist 공개.
8. 고객/디렉터가 정해진 주체로 셀렉 → submit_selection이 실제 보정 작업 생성.
9. 배정 보정가가 마스킹된 본인 작업을 수행 → 보정본 업로드·전달.
10. 고객 후기 캡처 → 직원 확인/resolve_request → campaign_claims와 전체 원본 공개·후속 알림.

각 단계에서 고객 화면·직원 처리·DB 상태·파일 공개·알림 원장이 일치해야 한다. 이후 REQ-013의 수정 요청과 3회 제한, 추가 보정 결제, 취소 등 변형을 연결한다. 개발 중 수동 큐·어댑터 대역을 쓰더라도 최종 출시 전 실제 알림톡의 동일 흐름을 검증한다.

## 10. 현재 산출물과 완료 증거의 경계

원문 조사 산출물은 [PRD](../01-product-requirements.md), [계정·권한](../reference/02-accounts-and-permissions.md), [디자인 시스템](../reference/03-design-system.md), [데이터·흐름](05-data-and-flows.md), 이 결정 문서와 [출처 기록](../reference/00-sources-and-traceability.md)이다. PRD에는 19개 요구사항·86개 수용 기준, 30개 상태와 별도 취소가 있고 데이터 문서에는 원문의 32개 테이블을 정리했다.

문서 검증은 로컬 링크 존재·중복 요구사항 ID·상태/테이블 수·출처와 제안 구분·문서 간 정책 일치를 대상으로 한다. 원문 열람 개수와 접근 제한은 출처 대장의 실제 기록을 사용하고 전부 읽었다고 별도 추정하지 않는다.

이번 요청으로 app 코드·설정·package.json·lockfile·SQL·DB·배포를 생성하지 않는다. 따라서 lint·typecheck·빌드·E2E·RLS·실제 알림톡 실행 결과는 아직 없다. 구현 검증과 운영 출시 통과는 이 문서의 향후 계획이며 문서 작성 완료와 구분한다.
