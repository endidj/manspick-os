# 맨즈픽 고객 앱

고객이 예약하고, 개인 링크로 촬영 준비부터 사진 수령까지 진행하는 Next.js 앱입니다. 고객 Figma 원본 화면 23개와 설계 메모 23개를 직접 읽고 화면을 구분했습니다. 색상·타이포그래피·공통 UI는 `@manspick/design-system`의 공개 경로를 사용합니다.

## 실행과 경로

루트에서 `yarn dev`로 API와 세 앱을 실행합니다. 고객 앱만 실행할 때는 `yarn workspace @manspick/user dev`를 사용합니다. 기존 로컬 D1/R2 데이터 초기화와 원격 배포는 하지 않습니다.

| 경로             | 역할                                                    |
| ---------------- | ------------------------------------------------------- |
| `/`              | 로컬 시연용 촬영 목록·신규 예약 진입                    |
| `/start`         | 옵션 → 기본정보·동의 → 실제 가능 날짜·시간 → 예약 접수  |
| `/s/[token]`     | 휴대전화 뒤 4자리 확인 후 개인 촬영 홈과 해당 업무 화면 |
| `/api/[...path]` | 같은 출처의 API 요청을 기존 Worker로 전달               |

샘플 링크와 신규 접수 응답의 체험용 확인 번호는 로컬 모드용입니다. 고객 조회·업로드·다운로드·업무 요청은 서버의 촬영 범위 및 파일 공개 검사를 통과해야 합니다. 쿠키를 클라이언트 저장소에 복제하지 않습니다.

## 고객 원본 대응 · 2026-11-06

원본 PNG와 메모를 기준으로 56px 상단바·24px 본문 여백·일곱 단계 표시·상태별 CTA를 재구성했습니다. 상태 resolver 회귀 검사로 결제·설문·준비·서울 자정 기준 당일·고객/디렉터 셀렉·보정·전달·후속·취소를 구분하고 임의 상단 탭을 제거했습니다. 준비 확인·계좌·지도·파일 폴더·현장 확정 셀렉 주체·사진 의상 분류·추가 결제를 실제 서버 계약으로 연결했습니다. 최초 상품 가격은 95,000/160,000/500,000원이며 운영자가 바꾼 상품과 예약 규칙은 신규 접수에 적용합니다. 기존 예약의 가격·마감은 보존하며 수정은 최대 3회입니다.

## 파일과 책임

```text
src/
  app/                     Next 페이지·메타데이터·오류 화면·API 프록시
  features/
    shell/                 원본 상단바·단계·본문 폭·하단 CTA
    booking/               실제 상품·기본정보·가능 일정·예약 접수
    survey/                네 페이지 설문·자동 저장·필수값·제출 완료
    customer/
      customer.tsx         인증·촬영 조회·업무 요청·업로드·장면 연결
      journey.ts           서버 상태 → 고객 화면·여정 단계
      customer-home.tsx     상태별 홈 7종·예약 요약·단계별 진입
      payment.tsx          실제 계좌·입금 유지 기한·직원 확인 요청
      preparation.tsx      안내 열람·의상·공유 설계·당일 실시간 진행
      photo-workspace.tsx  의상별 셀렉·추가 결제·수령·사진별 수정
      customer-scenes.tsx  후기 제출·공개 원본·후속 혜택
      presentation.ts      서울 기준 일정·고객용 패키지 표시
      view-types.ts        화면에 전달하는 데이터·요청 함수 타입
      uploads.tsx          공용 파일 선택·보호 다운로드 UI 조합
      demo-home.tsx        별도 개발용 샘플 진입
```

각 폴더 `index.ts`는 내보내기만 합니다. 화면 배치는 기능별 CSS Modules에 있습니다. 서버 실행부와 DB를 브라우저로 가져오지 않고 `@manspick/contracts`의 타입만 사용합니다. 새 의존성은 없습니다.

## 사용하는 공개 패키지

- `@manspick/design-system/components`: AppBar, StepHeader, Button, DateCell, TimeSlot, CheckItem, PhotoTile, Badge, Notice, EmptyState, Loading.
- `@manspick/design-system/patterns`: ChoiceCard, TextField, TextArea, RadioPills, InfoRow, SummaryCard, Dialog, UploadDropzone.
- `@manspick/design-system/styles`, `/icons`: 공통 서체·색상·타이포그래피·간격·상태 토큰과 원본 아이콘.
- `@manspick/domain`: 상태별 업무 단계. `@manspick/web/client`, `/format`, `/proxy`: 기존 요청·오류 처리·금액 표시·API 프록시.

## 실제로 연결한 동작

예약은 기존 catalog/calendar/start를 사용합니다. 패키지·쇼핑 변경 시 날짜와 시간을 초기화합니다. 이름·전화번호·결제 경로와 신고 금액·카카오 닉네임·개인정보/알림 필수 동의·마케팅 선택 동의를 제출합니다. 결제 금액은 신고 정보이며 실제 청구액은 서버 상품 스냅샷을 따릅니다. 기존 번호로 진행 중인 촬영을 조회하는 응답은 계정 존재 여부를 노출하지 않습니다.

개인 링크 인증 후 홈에서 업무별 화면으로 이동합니다. 입금 요청은 결제 확정과 구분하며 직원 확인이 필요합니다. 설문은 입력 900ms 뒤 직렬 저장하고 저장 성공 후 다음 페이지로 이동합니다. 얼굴 사진 및 해당 옵션의 체형·사이즈 필수 조건을 확인합니다. 후기 참여 거절과 포트폴리오 미동의도 저장할 수 있습니다. 제출·마감 이후 제한은 서버 규칙을 따릅니다.

준비 가이드를 열 때 실제 열람 기록을 저장하고 전체 확인 요청을 별도로 보냅니다. 의상 사진 필요 수량·D-2 기한, 공유된 설계·참고 사진, 실제 지도·주차 링크를 사용합니다. 촬영 당일 진행은 15초마다 갱신하며 화면을 떠나면 갱신을 중지합니다. 아직 확정되지 않은 현장 셀렉 주체는 설문 선호와 구분합니다.

후보 사진은 서버의 의상 번호·라벨로 필터링합니다. 고객 셀렉과 디렉터 셀렉의 제출 권한은 서버가 결정합니다. 기본 장수 초과 선택은 운영자가 설정한 단가(미설정 기본10,000원)로 실제 결제 대기를 만들고, 직원 확인 전 보정 작업이 시작되지 않습니다. 판매 중단 시 기본 포함 컷은 계속 제출할 수 있고 신규 유료 초과/추가 주문만 막습니다. 이미 접수한 주문 금액은 유지합니다. 결과 이후 추가 보정도 남은 후보로 실제 1회 주문을 생성합니다. 결제별 입금자 확인 요청과 계좌 복사를 연결했습니다. 보정본·원본 폴더 링크와 개별 보호 다운로드, 사진별 자유 의견을 묶은 최대 3회 수정, 후기 캡처 제출 → 직원 확인 → 원본 공개도 실제 응답을 따릅니다.

## 정책 차이와 남은 범위

원본의 구형 가격이나 무제한 수정은 사용하지 않습니다. 외부 플랫폼 선결제도 직원 확인 후 확정하며 임의 자동 확정하지 않습니다. 공통 상품의 할인 전 금액은 catalog의 `originalPrice`를 사용합니다. 올데이 헤어 포함 옵션은 별도로 중복 청구하지 않습니다.

설문 마지막의 추가 옵션은 상담 희망 답변으로 저장합니다. 이 답변이 실제 상품 주문이나 결제를 생성하지 않습니다. 지인 소개·블로그 후기 이벤트는 참여 안내와 직원 확인 경로이며 자동 캠페인 지급 계약은 아직 없습니다. 블로그 후기에 사진 2장 이상이 필요하다는 원본 안내를 유지합니다.

공식 카카오채널 URL·운영 계좌·실제 장소/가이드는 운영 설정이 필요합니다. 미등록 상태에서는 해당 사실을 안내하며 가짜 URL·계좌·지도·저장 성공을 만들지 않습니다. 실제 인증 안내 발송·결제 대행·자동 환불·외부 플랫폼 연동·알림톡·대량 ZIP 다운로드·이미지 재개 업로드·원격 배포는 제공하지 않습니다. 예약 레코드는 현재 API 계약에 따라 날짜·시간 확정 요청 때 생성되며, 기본정보만 입력한 시점에 중간 레코드를 만든 것으로 표시하지 않습니다.
