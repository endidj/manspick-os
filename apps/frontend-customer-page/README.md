# 맨즈픽 고객 앱

고객이 상품과 옵션을 고르고 여러 희망 일정을 제출하는 앱입니다. 직원이 수납을 확인한 뒤 고객은 설문을 작성하고, 배정된 디렉터가 확정한 촬영 일시와 장소를 개인 페이지에서 확인합니다. [제품 요구사항](../../docs/product-requirements.md)

## 실행과 경로

루트에서 `yarn dev`를 실행하고 [예약 시작](http://localhost:3001/start)을 엽니다. 로컬 고객 홈에는 가상 예약 링크와 휴대전화 확인 번호가 있습니다. [로컬 실행 안내](../../README.md#로컬-실행)

| 경로                                                                  | 역할                                               |
| --------------------------------------------------------------------- | -------------------------------------------------- |
| `/start` → `/start/details` → `/start/schedule`                       | 상품·옵션, 기본정보·결제 경로, 희망 일정 입력      |
| `/start/complete`                                                     | 이 탭에서 접수한 결과 확인                         |
| `/s/[token]`, `/s/[token]/payment`                                    | 휴대전화 뒤 4자리 인증, 내 촬영 홈, 입금 확인 요청 |
| `/social/kakao`, `/social/google`                                     | 설정된 로그인 공급자에서 인증 후 예약으로 복귀     |
| `/s/[token]/survey/1` ~ `/survey/4`, `/s/[token]/survey-complete`     | 설문 작성·자동 저장·제출 확인                      |
| `/s/[token]/preparation`, `/plan`, `/shoot-day` (같은 개인 링크 아래) | 준비 가이드·의상 사진, 공유된 촬영 계획, 당일 안내 |

자사몰 테스트 주문은 실제 청구 없이 접수합니다. 외부 플랫폼 선결제 고객은 플랫폼 닉네임을 입력하고 직원 확인을 기다립니다. 동일 번호로 진행 중인 예약이 있어도 응답에서 기존 고객의 개인 링크를 공개하지 않습니다. 카카오·Google 로그인 환경 변수와 콜백 등록 방법은 [서버 README](../server/README.md#환경과-검사)에 있습니다.

## 수정할 곳과 검증

- 예약 단계와 허용 URL은 [booking](src/features/booking/), 인증 후 화면과 서버 상태에 따른 다음 단계는 [customer](src/features/customer/)에 있습니다. 개인 링크를 재발급하면 이전 링크와 세션이 만료됩니다.
- [설문](src/features/survey/survey.tsx)은 입력이 멈춘 뒤 900ms에 자동 저장합니다. 최종 제출 시 `@manspick/domain`의 공통 규칙으로 전체 페이지의 필수 응답과 해당 사진을 검사합니다. 저장에 실패하면 입력을 유지합니다.
- 결과 사진 전달은 네이버 클라우드, 보정 의견 교환은 카카오톡을 사용합니다.

루트에서 `yarn test`로 예약·여정·설문 규칙을 검사합니다. 고객 앱을 실행한 뒤 아래 명령으로 실제 브라우저의 예약·인증·설문 이동과 뒤로 가기를 확인할 수 있습니다.

```powershell
$env:CUSTOMER_APP_URL = 'http://127.0.0.1:3001'
node --test tests/customer-navigation.browser.test.mjs
```
