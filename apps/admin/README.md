# 맨즈픽 운영 앱

직원이 고객 접수부터 촬영·셀렉·보정·후속 요청을 처리하는 Next.js 앱입니다. 데스크톱 운영 화면과 디렉터 모바일 화면은 로컬 API의 시연 데이터를 사용합니다.

## 실행과 로컬 인증

루트에서 `yarn dev` 실행 후 [운영 앱](http://localhost:3002)을 엽니다. 앱만 실행할 때는 `yarn workspace @manspick/admin dev`를 사용합니다. D1/R2 데이터는 초기화하지 않습니다.

역할 선택은 localhost의 `LOCAL_DEMO` 환경에서 가상 직원 계정으로 동작합니다. 대표·운영 직원·디렉터·보정가의 데이터 범위와 허용 동작은 서버가 검증합니다. 직원 이메일 링크 로그인은 [운영 설정](../server/README.md#환경과-검사)이 필요합니다. 고객 외부 알림 발송은 연결되지 않았습니다.

대표는 **운영 설정 → 운영자**에서 직원 이메일을 등록하고 역할·활성 상태를 바꾸거나 다른 계정의 전체 세션을 종료할 수 있습니다. 권한을 바꾸면 이미 발급된 로그인 링크와 세션도 회수됩니다. **변경 이력**에서 계정·설정·템플릿 변경을 확인할 수 있습니다.

## 화면 주소

| 업무 화면        | 로컬 화면                          | 실제 연결                                                                           |
| ---------------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| I-1 고객 보드    | `/?view=board`, `list`, `requests` | 네 운영 집계, 일곱 단계, 검색·기간·담당·상품·대기 필터, 직원별 필터 저장, 수동 접수 |
| I-2 고객 상세    | `/shoots/:id`                      | 결제·설문·준비 안내·설계·요청·알림·타임라인·메모                                    |
| I-3 배정·스케줄  | `/?view=calendar`                  | 실제 후보별 스킬·가능 일정·업무량, 주간 슬롯, 담당 변경, 관리자 휴무 저장           |
| I-4 현장 체크    | `/shoots/:id?screen=field`         | 여덟 체크·셀렉 주체·사유·현장 메모 저장, 전 항목 완료 검증                          |
| I-5 보정가       | `/?view=retouch`, `completed`      | 배정 작업, 보호된 셀렉 사진·요청, 보정본/수정본 업로드와 재시도·전달                |
| I-6 패키지·옵션  | `/?view=packages`                  | 관리자 상품 편집, 디렉터 수행 옵션·일곱 요일 보정가 기준 저장                       |
| I-7 안내 템플릿  | `/?view=templates`                 | 원본 15종 단계별 목록·구조화 조건·활성 저장, 조건에 맞는 실제 고객 미리보기         |
| I-8 후속 이벤트  | `/?view=followups`                 | 캠페인 저장, 후기·추가 보정 요청 조회·완료·반려                                     |
| I-9 디렉터 고객  | `/?view=my-customers`, `today`     | 서버가 배정 범위로 제한한 고객 목록과 기간·진행 필터                                |
| I-10 디렉터 관리 | `/shoots/:id?screen=manage`        | 설계·참고사진·준비 안내·메모 편집, 현장 체크·후보 업로드 이동                       |
| I-11 후보 올리기 | `/shoots/:id?screen=candidates`    | 의상 분류, 다중 축소 업로드, 진행·실패 재시도, 명시적 셀렉 열기                     |
| I-12 운영 설정   | `/?view=settings`                  | 관리자 계좌·동네·준비 가이드 저장, 실제 직원/운영 기준 조회                         |
| M-1 상태 변경    | 고객 상세 대화상자                 | 실제 현재 상태·전체 상태 선택·사유, 서버 전이 검증·취소                             |
| M-2 파일 링크    | 고객 상세 파일 링크 대화상자       | HTTPS 결과물 링크 저장·복사, 원본 후기 공개 조건 유지                               |

기존 `?view=notifications` 발송 기록 진입도 유지합니다. `profile`은 로그인한 디렉터의 실제 계정 정보만 표시합니다. 역할에 맞지 않는 메뉴 진입은 해당 역할의 기본 업무 화면으로 돌아가며 서버 권한 검증도 유지합니다.

## 파일과 공개 패키지

```text
src/
  app/                    Next 페이지·오류 화면·기존 API 프록시
  features/
    authentication/       직원 이메일 링크·로컬 역할 로그인·세션
    workspace/            순수 메뉴 모델·주소 탐색·화면 조립
    shell/                240px 사이드바·디렉터 모바일 하단 메뉴
    board/                운영 집계·검색·필터·보드/목록·수동 등록
    schedule/             배정 근거·주간 슬롯·휴무
    director/             내 고객·고객 관리·현장 체크·의상별 후보
    retouch/              보정가 작업 목록과 상세
    operations/           상품·템플릿·후속 이벤트·운영 설정·직원 계정
    shoot-detail/         상세 업무·요청·설문·업로드·상태/담당 변경
```

폴더의 `index.ts`는 재수출만 합니다. 화면 옆 CSS Modules는 레이아웃을 소유하며 색상과 글자 크기·굵기는 디자인 시스템의 의미·타이포그래피 토큰을 사용합니다. 원본의 blue500 흰 글자 조합을 유지합니다.

- `@manspick/design-system/components`: Button, Panel, NavItem, KanbanCard, StageBadge, Badge, CheckItem, AppBar, PhotoTile, TemplateBlock, Notice, Loading, EmptyState 등.
- `@manspick/design-system/patterns`: SectionHeader, TextField, TextArea, SelectField, ChipGroup, SettingRow, Tabs, RadioPills, InfoRow, Dialog, UploadDropzone 등. 상품/운영 탭은 flush 표현, 배정/상품 규칙/고객 선택은 SelectField, 템플릿 조건은 ChipGroup, 편집 가능한 상품 규칙 행은 SettingRow를 사용한다. 저장·권한·조건 판정은 앱과 서버에 유지한다.
- `@manspick/domain`: 상태·직원 역할·서울 날짜·슬롯 기준. 순수 메뉴 모델은 DS의 TSX 타입에 의존하지 않습니다.
- `@manspick/contracts`: API DTO·명령 타입만 가져옵니다. 앱이 DB나 서버 실행부를 직접 가져오지 않습니다.
- `@manspick/web/client`, `/format`: 세션 쿠키·API 오류·금액·날짜 표시를 재사용합니다.

## 보존한 동작과 경계

입금 확인, 준비 안내·촬영 설계 공유, 상태·담당 변경과 사유, 내부 메모, 취소, 셀렉 공개, 보정 전달, 요청 완료/반려는 실제 API를 호출합니다. 저장 실패 시 오류를 표시하고 입력·재시도 경로를 유지합니다. 내부 메모는 성공 후에만 지웁니다. 수동 접수는 기존 `/start`를 재사용하고 실제 가능한 날짜·시간과 필수 개인정보/서비스 안내 동의를 받으며 자동 배정·동시 예약 보호를 적용합니다.

상품 화면의 스팟·하/중/상·옵션 가중·수량·상품 별칭과 디렉터 자격은 실제 신규 예약에 연결합니다. 운영 설정 카드에서 입금 유지/마감, 예약 주 수, 기존 네 시작 시간의 노출, 설문/의상 마감과 추가 보정 단가를 저장합니다. 단가와 판매 여부는 상품의 사진 전용 추가 보정 항목을 함께 사용합니다. 기존 예약 기한·가격·주문을 일괄 변경하지 않으며 미정인 난이도 순위·카드 전체 비활성·보관/보상 정책은 동작을 발명하지 않습니다.

후보 사진은 브라우저에서 긴 변 최대 1600px JPEG로 축소합니다. 의상 번호와 이름을 전송하고 실패 시 파일·분류를 보존해 다시 시도합니다. 보정본·수정본은 원본 파일을 유지하며 선택한 원본 컷 연결을 전송할 수 있습니다. 업로드와 고객 공개는 별개입니다. 참고사진은 `plan_ref`로 저장하고 설계 공유 시 공개합니다. 셀렉 사진과 보정 이미지의 보호된 R2 경로·원본 스트림·보정가 개인정보 제한을 유지합니다.

현장에서 디렉터 셀렉으로 확정한 경우 후보 화면의 `디렉터 최종 셀렉`과 운영자 사진 탭에서 공개 후보만 의상별로 선택할 수 있습니다. `director-selection.tsx`가 공통 PhotoTile·Dialog·Button을 사용하고, `selection-model.ts`가 확정 주체·명령 권한·셀렉 진행 상태·기존 제출·공개 후보 ID를 검사합니다. 의상 필터와 업로드 화면을 오가도 선택을 유지하며 1~100장을 서버 `submit_selection`으로 제출합니다. 기본 수량 초과분은 현재 운영 단가(미설정 기본10,000원)를 최종 확인하고, 서버가 생성한 추가 보정 입금 대기를 표시합니다. 입금 확인과 보정 작업 생성은 기존 서버 검증을 따릅니다. 제출 성공 후에는 저장한 선택을 읽기 전용으로 표시하고, 실패하면 선택과 재시도 경로를 유지합니다. 원본 I-4의 현장 확정과 I-11의 후보 공개 뒤를 연결한 기능이며 별도 원본 화면이 없는 최종 선택 영역은 고객 앱의 기존 선택 흐름과 디자인 시스템을 재사용합니다.

안내 템플릿은 단계·패키지·부가서비스·발송 담당 조건을 각각 AND로, 각 조건의 여러 값은 OR로 적용합니다. 빈 조건은 제한하지 않습니다. 원본에서 본문을 확인한 준비물 안내를 기본 선택하며, 나머지 원본 안내는 운영자 검토 전 비활성 초안으로 구분합니다. 네비게이션의 원본 설문·일정 그룹 표기와 서버에서 사용하는 실제 단계 번호를 구분합니다. 고객 상세와 디렉터 화면은 `/shoots/:id/messages`가 반환한 활성·조건 일치 템플릿과 보호된 실제 문구를 표시하며 `/shoots/:id/messages/:templateKey/complete`로 멱등적인 수동 완료 기록을 저장합니다. 미저장 미리보기는 고객 링크 등 DTO에 없는 변수를 중괄호 그대로 표시합니다.

직원이 카카오채널에서 문구를 직접 발송한 뒤 완료를 누르면 서버에 수동 완료 기록을 저장합니다. 공식 카카오 주소를 등록하면 채널 열기 버튼을 연결할 수 있습니다.

## 검증

루트의 `yarn test:admin`은 로컬 Chromium으로 고객 등록·상세 저장과 직원 등록·권한 변경·세션 회수를 확인합니다. 직원 계정 저장 중 충돌하면 입력을 유지하고, 사용자가 다시 불러오면 최신 계정 상태를 표시하는지도 검사합니다. 테스트는 API 응답을 모의합니다.

`tests/admin-views.test.ts`는 운영 메뉴, 역할별 허용 화면, 기존 주소 호환, ID 인코딩·상세 화면 선택과 템플릿의 활성·단계·상품·옵션·직원 조건 경계를 검증합니다. 앱 TypeScript·ESLint 0 warnings·Prettier와 이 회귀를 로컬에서 검사합니다. 전체 회귀·통합 API·Next 빌드·브라우저 시각 비교는 루트 검증에 합칩니다. 원본 PNG를 직접 확인한 구현 범위와 모든 상태의 픽셀/역할 E2E 검증 완료는 구분합니다.

`tests/director-selection.test.ts`는 현장 미확정·고객 셀렉·권한 없음·종료·기제출 상태를 잠그고, 비공개/다른 종류/중복 후보와 미배정 보정가를 제출에서 제외하며 의상 간 선택 순서와 100장 상한을 검증합니다.
